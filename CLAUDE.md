# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Nix flake that builds a reproducible Alacritty terminal, bundled with a curated set of CLI tools (zsh, tmux, bat, ripgrep, fd, starship, delta, navi, claude-code, …) each wrapped so they load their configuration from this repo's `sources/` tree.

## Common commands

Enter the dev shell first (`nix develop` — direnv will do it automatically via `.envrc`). Its helpers (`dev`, `bdl`, `tools`, `smoke`, `watch`) are defined in `devshells/terminal.nix`; `h` prints the list.

`lefthook run pre-commit` runs the git hooks locally. Not a dry run: the `auto-commit` job commits whatever is staged.

## Architecture

- `packages.tools` — a `buildEnv` of every tool. `pathsToLink = [ "/bin" ]` to avoid config-file collisions between wrappers (e.g. `fd` and `ripgrep` both ship a `.config/ignore`).
- Apart from `firefox-mcp`, the in-repo packages are Go binaries with no flake output of their own, one per directory under `packages/` (`git-<x>` lives in `packages/git/<x>/` and `claude-<x>` in `packages/claude/<x>/`: the directory drops the prefix, while the `go.mod` module, which names the binary, and `pname` keep it). The sandbox launcher, its fail-closed helpers, `git-shim` and `git-allowlist-hook` are not built here: they come from the `claude-sandbox` flake input (see the claude sandbox section).
- `lib.mkTerminal` / `lib.mkTools` — reusable builders for downstream flakes. Both take `{ system, configPath ? ./sources }` (not `pkgs`); they call `mkPkgs system` internally so consumers can't accidentally pull stale versions of version-sensitive tools through their own `nixpkgs` lock.

### `lib/files.nix` (local) + `permeance` (flake input)

Two namespaces, paired to implement the **permeance** pattern (build-time bundled tree + runtime override knob): `files.mkConfig` (in `lib/files.nix`) links the bundled `sources/` entries into each wrapper's `$out`, and `permeance.installLauncher` (from the `permeance` flake input — see `~/permeance` / `github:Runeword/permeance`) writes the launcher that resolves them from `$PERMEANCE_ROOT` at exec time.

Setting `PERMEANCE_ROOT=/path/to/sources` at launch redirects every wrapper's config var/flag to the live tree — no rebuild, no `--impure`. The flake is always pure (no `getEnv`); the dev/bundled switch lives entirely at exec time. The launcher itself validates `$PERMEANCE_ROOT` at startup: must be absolute, must point at an existing directory.

This pattern is the inverse of NixOS impermanence: same trick (symlink at a Nix path opens onto a non-store path with different durability rules), opposite goal. Impermanence escapes ephemeral-root volatility by pointing at a persistent disk; permeance escapes store immutability by pointing at the editable working tree. Unit tests for the launcher renderer live in the `permeance` repo; this flake's `checks.unit-tests` only asserts wrapper-level invariants (e.g. "every wrapper has a smoke test").

### The claude sandbox (`github:Runeword/claude-sandbox`)

On Linux, `__claude` (in `sources/.config/shell/functions/claude.bash`) never runs `claude` directly — it prefixes `claude-sandbox`, the launcher from the `claude-sandbox` flake input, which re-execs into an unprivileged bubblewrap namespace. **The gate fails closed**: a missing `bwrap` or a non-executable launcher aborts with a message rather than starting an unsandboxed claude, and `CLAUDE_SANDBOX=0` is the explicit escape hatch, not a fallback. Claude Code's own `/sandbox` is not used here because its Linux seccomp filter blocks `socket(AF_UNIX, …)`, which severs the nix-daemon socket; it also only ever wrapped Bash, while this wraps the whole process tree — file tools, hooks, and MCP servers alike. Three security-critical steps are extracted from the launcher into fail-closed, table-tested Go binaries on the tools-env PATH that it invokes by bare name — `claude-cwd-gate` (the cwd refusal gate), `claude-ssh-sanitize` (builds the sanitized `~/.ssh` copy), and `claude-seccomp-bpf` (emits the TIOCSTI/TIOCLINUX seccomp filter) — each aborting the launch if missing rather than starting a weaker sandbox. A fourth, `claude-egress-proxy`, is the network filter of credential sessions, run on the host and inside the namespace, and fails closed the same way; the rest of the launcher is bwrap orchestration and stays bash. The launcher and its helpers live in [Runeword/claude-sandbox](https://github.com/Runeword/claude-sandbox), which tests them itself; a change to any of them is made there and reaches this repo through `nixtok nix flake update claude-sandbox`, run from a plain terminal: the repo is private, and `nixtok` injects the GitHub token from `pass` (`nix/github-token`), which a sandboxed session cannot decrypt.

What that means when working in this repo:

- **`sources/` is read-write inside a sandboxed session, except for what the host executes on its own.** `$PERMEANCE_TREE` is bound read-write, so an edit there is live on the host at once: the next host shell sources it and tmux runs it, before anyone has reviewed it. So the launcher re-pins the auto-executed part read-only from the host copy, on top of the bind, as listed in `sources/.claude/sandbox-pins` (read at every launch, and always pinned itself): `.claude/` (settings, hooks, plugin `.mcp.json` manifests, rules, `git-allowlist.toml`), the shell startup chain (`.config/zsh`, `.config/bash`, `shell/{xdg,variables,aliases}.sh`, and the glob-sourced `shell/functions/`, which holds `claude.bash`), the leader-key command table `shell/leader.toml` (whose picked chord the leader widget runs in the host shell), `.config/git` (a `core.hooksPath` there would sidestep the `.git/hooks` pin), `.config/delta` (git's pager, which runs the command its config's `pager` key names), and `.config/direnv`. Each pin's parent directories are anchored as mount points first (`__cs_anchor`; the launcher derives the anchors from the pins): a directory that merely contains a pinned mount can be renamed and recreated writable, so without anchors the pins would not hold. Those files are edited from a plain terminal; a session that needs one changed writes its candidate elsewhere and hands over the copy. The rest of the tree stays writable and is reviewed after the fact, `git diff -- sources` and `git checkout -- sources` on the host: on-demand tool config (bat, navi, ripgrep, readline, nvim-fzf, tree-sitter), the fzf scripts in `shell/scripts/`, and, deliberately, the tmux, starship and alacritty configs, which the host also runs unprompted but which are the repo's main editing target; add them to `sources/.claude/sandbox-pins` if that trade-off changes. In bundled mode `$PERMEANCE_TREE` is a store path and nothing is bound. What stays re-pinned read-only unconditionally, with no flag to lift it: `$PWD/.direnv`, `$PWD/.git/{hooks,config}` (with `.git` anchored), `lefthook*.yml`, direnv's `source_url` CAS, and, where present, Claude Code's project-level `$PWD/.claude/{settings.json,hooks,agents,commands,skills}` and `$PWD/.mcp.json` (`settings.local.json` stays writable because claude writes it; instead `claude.bash` cuts it at each launch to the permission rules claude writes there, and empties the MCP server lists in the profile's `.claude.json`, which would start without approval) — host-executed or self-granting, and never what a config-editing session needs. (Cost: `git config`/`git remote` writes are refused inside the sandbox; reads and staging are unaffected.) An overlay with a host-side apply step (`claude-sources-apply`) guarded the whole tree until 2026-09-18 and was removed as too much workflow; the pins above replaced it the same day for the auto-executed subset.
- **The cwd is the writable region**, so the launcher refuses to start from `$HOME`, an ancestor of it, an XDG root, or inside a tree the desktop session executes at login. `--check-cwd` runs exactly that gate and exits, which is how `claude.bash` reports a refusal from the calling shell (a `tmux new-window` pane clears on death).
- **`~/.cache/nix` is a private tmpfs inside the sandbox**, so nix's eval/fetcher caches start cold each session and cannot be poisoned for the host. `~/.ssh` is replaced by a sanitized copy (config, its `Include`s, `known_hosts`, and one `.pub` per `IdentityFile`); auth still works through the re-bound agent socket, but no private key enters the namespace.
- **The network is deliberately not isolated** — bwrap offers no domain filtering — so this is a boundary against filesystem damage and credential reads, not against exfiltration. The exception is a session holding a credential (`gh`, `jira` or `firebase`, picked in the leader `cc` connection picker, `__claude_connect` in `claude.bash`, which also adds MCP plugins on top of a plain session; each is claude's own credential, read from a `claude/` entry in `pass`, never your login): it gets no network of its own (`--unshare-net`), and everything it sends goes through `claude-egress-proxy` on the host, which lets through only the hosts the launcher lists (Claude's API, GitHub, nix caches, npm/PyPI, the session's service) and refuses a listed name that resolves to a local or private address. `CLAUDE_SANDBOX_NET_ALLOW` adds hosts for one session; refusals are logged to `$CLAUDE_CONFIG_DIR/egress.log`. ssh and anything that ignores the proxy variables have no network there. Nor is the nix-daemon socket: if the launching user is in nix's `trusted-users`, that socket is a root-equivalent hole and the launcher says so at startup.
- macOS gets Claude Code's built-in Seatbelt sandbox instead (bubblewrap is Linux-only, and Seatbelt can allow the nix-daemon socket by path). Per-OS stances live in overlays merged into the provisioned profile by `__claude_provision_sandbox_overlay`: `sources/.claude/settings.darwin.json` turns the built-in sandbox on and carries the Seatbelt config, while `sources/.claude/settings.linux.json` turns it off — recent claude-code enables it by default, but it can't nest inside the bubblewrap jail (`--disable-userns`), which replaces it. Seatbelt only wraps Bash commands, so the per-session credential opt-ins (`jira`/`firebase` in the `cc` picker) get their own macOS launcher, `claude-macos` (from the same input), which `claude.bash` puts in front of claude only when one is set: it reads the credential from `pass` on the host and hands it over through the environment, the Linux launcher's job there. `settings.darwin.json` does what the Linux masks do: `Read` deny rules keep the same credential stores (the personal `firebase login` in configstore, gcloud, `~/.ssh`, shell history, and the rest) away from both the file tools and sandboxed commands. `enableWeakerNetworkIsolation` lets Go CLIs reach the trust service they verify TLS through, so `gh`, `tofu` and `terraform` run inside Seatbelt; only `jira` runs outside it (`excludedCommands`), since its session reaches `api.atlassian.com`, which the sandbox's domain list does not name.

The header comment of `launchers/claude-sandbox.bash` in that repo is the authoritative description of the boundary, including what it deliberately does *not* cover.

#### Editing `sources/` from inside a sandboxed session

Edit the writable part like any other directory: Edit/Write, `shellcheck`, `bash -n`, `nix build .#checks.x86_64-linux.<wrapper>` and `smoke` all see the edits, and so does the host, immediately (a *new* file must be `git add`-ed before nix sees it, as for any flake). A write to a pinned path fails with `Read-only file system`: that is the pin, not a broken mount. For those, write the candidate under a writable path (`/tmp/claude-scratch/<task>/` is shared with the host), lint it there (`bash -n`; `shellcheck` run from `sources/.config/shell/` so `.shellcheckrc` applies; `shfmt -d -i 2 -ci`), and hand over the per-file `cp` for a plain terminal. A syntax error in `.zshrc` or `claude.bash` breaks the next host shell, so lint a shell file before handing it over. At handover, say what changed and that `git diff -- sources` on the host shows it.

Do **not** hand-author patches for `sources/`, and do not reach for a `git worktree` as a workaround: a worktree reproduces `lefthook.yml`, `.envrc`, and `flake.nix` at paths none of the launcher's relocks cover (they pin `$PWD/lefthook.yml`, `$PWD/.git/config`, `$PWD/.direnv` by exact path), so running `lefthook` or `cd`-ing into it on the host would execute sandbox-written content.

The pinned set above needs a plain terminal. The rest of the repo — `CLAUDE.md`, `flake.nix`, `wrappers/`, `packages/`, `lib/`, `devshells/`, `modules/`, `overlays/`, `infra/` — is directly writable. `.git/config`, `.git/hooks`, `lefthook*.yml`, and the project-level `.claude/` entries are refused unconditionally and no workflow lifts them.

### Infrastructure (`infra/`)

OpenTofu config for this repository's GitHub settings. State is local (`*.tfstate` gitignored) — bootstrap is import-based, not greenfield apply, since the repository already exists; see `infra/README.md` for the import sequence.

### CI (`.github/workflows/`)

`ci.yml`'s matrix fans into a stable-named `check` aggregate job — that name is the required-status context in branch protection (managed by `infra/`), so don't rename it. The private inputs' token reaches nix only through `NIX_CONFIG` in the steps that fetch them, never `/etc/nix/nix.conf`, which is world-readable to builds that run unsandboxed on macOS. Dependabot proposes a revision once it is 7 days old (`cooldown`), and `dependabot-auto-merge.yml` leaves an update that edits `flake.nix` (an input's ref, not just its lock) to a person.

## Testing

New code ships with the test its layer uses, and `smoke` (`nix flake check -L --keep-going -j auto`) must pass before a change is done — a change without its test is not finished. `smoke` builds every `checks.*` derivation; the terminal's smoke test alone pulls every tool in via `makeBinPath tools` (see `wrappers/alacritty.nix`), so the whole graph — wrappers, terminal, and each custom binary's `go test` — is exercised transitively. Match the mechanism to what you added:

- **A wrapper (`wrappers/*.nix`), new or changed** — attach `passthru.tests.smoke = permeance.tests.mkSmoke { name; description; script; }`. Presence is enforced: `lib/tests-unit.nix`'s `testAllWrappersHaveSmoke` fails the `unit-tests` check if any wrapper lacks one. Test **behaviourally** — invoke the wrapped binary and assert on an observable effect of the bundled config, not that a file exists — using the `ok`/`fail` helpers and isolated `$HOME` the harness provides (see `wrappers/fd.nix`: the bundled ignore hides `node_modules`; `wrappers/git.nix`: bundled global-config keys load). When a tool has no sandbox-friendly config probe (needs auth/network), a binary-executes check is the documented fallback (`wrappers/claude.nix`, which also asserts that every command `settings.json` names resolves on claude's PATH and that `claude-statusline` renders a fixed payload, so a change to the status line's output updates that expected line). Rewiring a wrapper's config means updating its smoke test to assert the new behaviour. The runtime `$PERMEANCE_ROOT` override can't be exercised inside the sandbox (no live working tree is reachable there), so it isn't tested.

- **A Go binary (`packages/<name>/`, or `packages/git/<x>/` / `packages/claude/<x>/` for `git-<x>` / `claude-<x>`)** — add `main_test.go` beside `main.go`. `pkgs.buildGoModule` runs `go test` in its check phase, so the test runs on every build with no extra flake wiring — the binary is a build dependency of the wrappers/terminal that the checks build. Follow the table-driven, stdlib-`testing` style that every Go binary under `packages/` already ships.

- **A pure-eval invariant or `lib/` helper** — add a `test*` attribute (`{ expr = …; expected = …; }`) to `lib/tests-unit.nix`; `pkgs.lib.runTests` runs it at eval time and `checks.unit-tests` fails the build (emitting the JSON failure list) on mismatch. Use this for structural facts about the flake, not for behaviour that needs a running binary.

- **Shell or config under `sources/`** — no unit harness covers it directly; validate syntax (`bash -n` and `shellcheck` for shell, `nix-instantiate --parse` for `.nix`) and, when the change has an observable effect, extend the owning wrapper's smoke test to assert it (the config is loaded behaviourally through that wrapper — e.g. a zsh change is exercised by `wrappers/zsh.nix`'s test). Inside a sandboxed session these run against the live tree, or against the scratch candidate for a pinned file; `smoke` does too. The sandbox launchers come from the claude-sandbox input, which tests them itself; `wrappers/claude.nix`'s smoke test dry-runs them against this tree: `claude-sandbox` with a stand-in `bwrap` that prints its argv, asserting the pins `sources/.claude/sandbox-pins` names and their anchors, so a change to that list updates that test, and `claude-macos` (plain bash, so on every platform) with a stand-in `claude` that records what it was handed.

Iterate on one check with `nix build .#checks.<system>.<name>` (e.g. `.#checks.x86_64-linux.fd`) before the full `smoke` run.

## Conventions

- `flake.nix` stays thin — real logic lives in `packages/`, `wrappers/`, `lib/`, `modules/`, `overlays/`, `devshells/`.
